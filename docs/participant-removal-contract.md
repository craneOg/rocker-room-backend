# P-07 및 API-030·058·060 처리 계약

2026-11-09 기획 확정 내용을 반영한 명세 보완이다. 기존 API 설명의 “팀·곡 원본 유지”는
팀·곡 엔티티의 보존을 의미하며, 대상자의 배정 연결을 보존한다는 의미가 아니다.

최신 Notion API 명세의 설명 속성과 처리 규칙에도 같은 기준을 반영했다:
[API-030](https://www.notion.so/09521457734682b7a6a701130906a89c),
[API-058](https://www.notion.so/bf821457734682778ff9819b21b17680),
[API-060](https://www.notion.so/a57214577346835c9dea0189cfa83c1a).

## P-07 — 철회·거절·소속 해제

- 공연 참여 행은 삭제하지 않는다. 거절은 REJECTED, 철회·소속 해제는 WITHDRAWN으로 전환한다.
- 대상자의 team_member 및 song_session_member 연결 행만 물리 삭제한다.
- 팀·곡 자체와 다른 참여자의 배정은 유지한다. 단, 아래 N4 표에 따라 제거 대상자가 팀장인 DRAFT 팀은 삭제한다.
- 팀장인 경우 해당 API의 후임 지정 또는 자동 승계 규칙을 먼저 수행하고 연결을 삭제한다.
- 재참여는 참여 행만 재활성화하며 이전 팀·곡 배정을 자동 복원하지 않는다.
- 삭제 전 영향 정보를 수집한다. 승계·연결 삭제·상태 전이·감사 기록은 하나의 트랜잭션으로 처리한다.

## API 설명 보완

| API | 처리 |
| --- | --- |
| API-030 소속 해제 | DRAFT·ACTIVE·LOCKED 공연의 유효 참여(APPLIED·APPROVED)를 WITHDRAWN으로 전환하고 대상자의 배정 연결을 제거한다. FINISHED·CANCELED 공연의 참여 기록과 과거 편성은 변경하지 않는다. |
| API-058 참여 거절 | 대상 참여 행은 REJECTED로 보존하고 대상자의 배정 연결을 제거한다. |
| API-060 참여 철회 | 대상 참여 행은 WITHDRAWN으로 보존하고 대상자의 배정 연결을 제거한다. |

## 팀장 승계 기준 (N4, 2026-11-10 확정)

| 처리 사유 | APPROVED 승인 팀 | SUBMITTED 심사 대기 팀 | DRAFT 작성 중 팀 |
| --- | --- | --- | --- |
| 공연 참여 본인 철회 | 남는 유효 팀원이 있으면 후임 지정 필수 | 남는 유효 팀원이 있으면 후임 지정 필수 | 삭제 |
| 관리자 거절·참여 해제 | 지정 후임 우선, 미지정 시 자동 승계 | 지정값을 사용하지 않고 자동 승계 | 삭제 |
| 동아리 소속 해제·서비스 탈퇴 | 지정 후임 우선, 미지정 시 자동 승계 | 지정값을 사용하지 않고 자동 승계 | 삭제 |

- 본인 철회는 서버가 요청자와 대상자 및 거절 여부로 판정한다. 임원도 본인 참여를 철회하면 본인 철회 규칙을 적용한다.
- 후임은 대상을 제외한 유효 팀원이다. 참여 상태 APPLIED·APPROVED, 소속 상태 ACTIVE·ON_LEAVE·GRADUATED를 허용하며 객원·졸업생을 일괄 배제하지 않는다.
- 자동 승계는 team_member.created_at, 같은 시각이면 team_member.id가 빠른 순이다. 후보가 없으면 팀장은 NULL이다.
- DRAFT 팀 삭제와 SUBMITTED 자동 승계(본인 철회 제외)에서는 요청의 후임 지정값을 소비하되 사용하지 않는다.
- 처리 대상자가 팀장이 아닌 팀을 지정한 요청이나 중복 지정은 거부한다.
- DRAFT 삭제 시 팀원 연결 전체와 일정의 팀 연결을 제거하고 곡의 candidate_team_id·assigned_team_id를 NULL로 바꾼다. 곡·일정 엔티티와 다른 사람의 곡별 연주자 연결은 보존한다. 변경된 곡의 version도 증가시킨다.
- 영향 정보는 삭제 전에 수집한다. 이 표는 진행 중 공연의 유효 참여 제거에 적용하며, 소속 해제로 FINISHED·CANCELED 공연의 과거 편성을 변경하지 않는다.
- 공통 서비스 TeamLeaderSuccession에 서비스 탈퇴 모드를 제공한다. 서비스 탈퇴 API 자체는 현재 저장소에 구현돼 있지 않으므로 해당 API 구현 시 이 서비스를 연결해야 한다.

## 승계 안내 (N5/U-06)

- 임원 권한 승계 시 후임 사용자에게 ADMIN 미확인 안내를 생성한다. club_id와 user_id만 연결하며 team_id·performance_id는 NULL이다.
- 공통 팀장 승계에서 실제 후임이 정해졌을 때 후임 사용자에게 TEAM_LEADER 미확인 안내를 생성한다. 동아리·공연·팀 ID를 함께 기록한다.
- 후임이 없거나 DRAFT 팀을 삭제하는 경우 안내를 생성하지 않는다.
- 안내의 confirmed_at은 NULL이며, 이전 임원·팀장의 이름이나 별도의 개인정보 문구는 저장하지 않는다.
- 안내 생성은 승계 트랜잭션에서만 실행하며, 승계나 후속 처리가 실패하면 역할·배정·감사 기록과 함께 롤백한다.
- 현재 저장소에는 API-135 조회·확인 구현이 없으므로, 이 변경은 기존 succession_notice 테이블에 안내를 저장하는 범위를 담당한다.

## LOCKED 공연 보호 규칙 (N3)

API-060의 직접 철회와 API-030의 소속 해제는 participant 도메인의 같은 정책을 사용한다.
공연 행을 잠근 뒤 최신 상태를 확인하고, 처리 대상에 LOCKED 공연의 유효 참여가 있으면
사유를 요구한다(400 VALIDATION_ERROR, REASON_REQUIRED).
대상자를 제외했을 때 확정 곡의 승인 연주자가 0명이 되면
422 RULE_VIOLATION(reason: SONG_WITHOUT_PLAYER)로 거부하며, 영향 곡 ID를 details.field에 표시한다.
검사 실패 시 소속 해제 전체를 롤백하므로 다른 공연의 변경도 반영되지 않는다.
성공하면 참여 철회 감사와 함께 LOCKED_EXCEPTION_EDIT를 같은 트랜잭션에 기록한다.
